# Instructions for coding agents

This file gives instructions to AI coding tools that work in this repository. It adds to [CONTRIBUTING.md](CONTRIBUTING.md), which applies in full.

## The repository

mixOmics is an R package released through Bioconductor.

- `R/`: the source. Most of the help text is written as roxygen2 comments above each function.
- `tests/testthat/`: the tests (testthat, with vdiffr snapshots of the plots in `_snaps/`).
- `examples/`: the example code that the help pages include through `@example` tags.
- `man-roxygen/`: the roxygen2 templates that `@template` tags use.
- `vignettes/vignette.Rmd`: the vignette.
- `data/`: the datasets that come with the package.
- `inst/README.Rmd` and `inst/README-WhatsNew.Rmd`: the sources of `README.md`.

## Commands

Run these in R, from the top of the repository:

```r
devtools::document()        # regenerate man/ and NAMESPACE from the roxygen2 comments
devtools::test()            # run the tests
devtools::check(args = "--no-manual", error_on = "warning")   # the check that CI runs
BiocCheck::BiocCheck(".")   # install it first with BiocManager::install("BiocCheck")
```

After setting up R and Bioconductor, CI installs the package's dependencies with:

```r
remotes::install_deps(dependencies = TRUE, repos = BiocManager::repositories())
```

## Generated files: never edit these by hand

- `man/*.Rd` and `NAMESPACE` are generated by roxygen2. Edit the comments in `R/`, or the files in `examples/` and `man-roxygen/` that they include, and run `devtools::document()`.
- `README.md` is rendered from `inst/README.Rmd` and `inst/README-WhatsNew.Rmd` by the Render README workflow, when a pull request into `master` changes them or `DESCRIPTION`.
- `tests/testthat/_snaps/` is written by the tests. A changed snapshot usually means a changed plot: say so in the pull request, and do not accept a new snapshot only to make a test pass.

## Rules

- Keep each pull request to one topic, and keep the change as small as the task allows.
- Add or update a test for every change in behaviour.
- If a change alters a numerical result or a plot, say so plainly in the pull request.
- Do not add, remove or upgrade a dependency in `DESCRIPTION` unless the task asks for it.
- Do not change the `License`, `Authors@R` or `Version` fields of `DESCRIPTION`, and do not remove or edit author, copyright or licence lines in any file, unless the task asks for exactly that.
- Do not call `library()` or `require()` in package code, and write `TRUE` and `FALSE` in full. BiocCheck reports both.
- Do not commit credentials, tokens or keys.
- Do not push to Bioconductor. Releases are made by the maintainers.

## Pull requests and issues

- Propose changes through a pull request. Never push to `master`, and never merge a pull request.
- Fill in every written part of the pull request template, and leave its boxes for the person who opens the pull request. Give the pull request a plain sentence as its title that says what changes, for example "Fix the legend order in plotIndiv".
- Open an issue only through one of the issue forms. Fill in each text box with facts from the task, and write "unknown" rather than guess. Leave the tick boxes, and any choice you cannot make from the facts, to the person you are working for, and give them the filled-in text to submit.
- Do not close, label, assign or comment on an issue or a pull request unless the person you are working for asked you to.
- A contribution is accepted only when a signed mixOmics contributor agreement covers it (see CONTRIBUTING.md). Before you prepare a pull request, ask the person you are working for whether one does, and if not, tell them how to ask for it. Never sign it for them, and never say that it is signed when you do not know.
- Every commit needs a `Signed-off-by` line, which certifies the Developer Certificate of Origin ([DCO](DCO)). That certification is the person's, not yours: add the line, with their name and address, only when they have told you to, and never in your own name.
- Follow the [Code of Conduct](CODE_OF_CONDUCT.md) in everything you write in the repository.
- If a non-trivial part of a change was written by an AI tool, or copied from another project, say so in the issue and in the pull request description, as [Bioconductor's policy](https://contributions.bioconductor.org/ai-policy-third-party.html) asks, for example `Assisted-by: <name of the tool>` or `Code copied from: <source>`.
- Do not tick a box in a template, or sign anything, on a person's behalf. The person who opens the pull request answers for it.
- If a task is unclear, or would break one of these rules, stop and ask the person you are working for.

## Style

- Follow [Bioconductor's guidance on R code](https://contributions.bioconductor.org/r-code.html).
- Commit messages use the form `type(scope): summary` (the scope may be left out), as described in CONTRIBUTING.md.
- A branch that you create in this repository must have a name that starts with `feat/`, `fix/`, `chore/`, `docs/`, `refactor/`, `test/` or `release/`.
